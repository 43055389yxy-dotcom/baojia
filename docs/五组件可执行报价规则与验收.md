# 五组件可执行报价规则与验收

## 目标与边界

客户继续粘贴自然语言；不会增加一个要求客户重新手填所有 AWS 字段的流程。现有逐组件清洗、架构选择、官方目录、四层 IR 和事实发布闸门保留。此次首先落地“同一份声明生成公式说明与实际用量”，不声称已经重写全订单语义理解、覆盖所有 AWS 收费模式或验证了所有客户原话。

## 一次明确的设计细节

1. 需求与选型分开。指定型号/必须 x86 属于约束；全局 ARM 是偏好。型号例外仍按组件确认，不能借本次迁移自动放宽要求。
2. 资源组、磁盘角色、每台值和整组总量分开。已给出两种表示时校验一致，不相加、不重复乘数量。多个数据盘分别保留索引和官方计费身份。
3. 使用已经归一化的字段与单位。此层不重读客户的 G/T 原话；GB/GiB、TB/TiB 的识别和证据仍属于需求解析。缺失不能改成零；零用量不提交正数收费行。
4. 默认值单列。执行器记录自己采用的规则默认值（例如已存在的 EC2 开机比例 100%），不将其写入客户事实。全局地区、时长、付款方式等仍由已有工作流负责确认与披露。
5. 独立服务模块维护字段和表达式。通用执行器只允许有限的加减乘除、最大值、候选值一致性校验和数组逐项运算；不运行 AI/Python/JavaScript 公式字符串。
6. 不混用官方单价口径。普通 RDS 使用匹配部署模式的官方 SKU，不能在已经包含主备的单价上再乘一次主备数；Aurora 不走普通 RDS 表达式。
7. 未迁移不等于免费。备份、额外性能、取回、预留等收费项不能仅凭模板中出现了字段就宣称已报价。它们继续经过原有适配器与事实消费检查，仍需逐项迁移和独立验收。
8. 模板版本与计算底稿。每条已迁移用量记录规则 ID、内容指纹、计价单位、输入、默认值、作用域、数组索引、结果。发布前复算，不执行底稿的文本公式。
9. 价格层保持官方来源。计算底稿只有用量，没有自行编造价格。阶梯、共享免费额度、账号费率和跨组件汇总是整单计价问题，不允许在每个组件各减一次免费额度。此轮没有改写这部分算法。
10. 商业报价与云成本分开。税费、销售折扣、加价和汇率需另有明确口径，不能混入 AWS 原价。本轮仍沿用现有 USD/官方核价路径。
11. 缺少信息时保留已知事实并指出具体阻塞字段，不能静默漏掉费用。Standard 与 IA 请求分配、备份实际容量、ALB 多口径关系等不能由模型凭空补齐。
12. 历史结果不伪装成新结果。旧报价没有计算底稿时页面不显示该入口；新的规则版本不能复用旧底稿发布，需重新生成报价。

## 本轮实际接入的运行路径

| 独立模块 | 已接入插件的可执行规则 | 本轮没有完成的扩展 |
| --- | --- | --- |
| `ec2.py` | 按需实例小时与百分比、系统盘总量/单台量对账、逐块数据盘容量、公网出流量 | 快照容量模型、额外 IOPS/吞吐、预留与 Savings Plans 算法迁移；区域内流量表达式已声明但尚未在此插件接入 |
| `rds.py` | 普通 RDS 的部署 SKU 小时、分配存储；MySQL/PostgreSQL 的 Single-AZ/Multi-AZ 回归 | Aurora、只读副本独立建模、额外性能、额外备份和保留策略的完整收费模型 |
| `redis.py` | 总节点/拓扑一致性、节点小时；总节点不再乘部署数量 | Serverless、备份用量模型、预留费用迁移 |
| `s3.py` | 容量、读写请求、公网出流量；每资源/合计作用域；已知零请求消费 | 多存储类别的用量分配、IA 取回、最小对象/存储期限、其他高级收费项 |
| `alb.py` | 实例小时、直接平均 LCU、组件/单 ALB 月流量、标准 EC2/IP 目标的四维估算 | Lambda 目标、mTLS、大证书、按小时波动曲线、混合统计口径自动解释 |

`adapter_required` 仅表示该输出尚无此执行器的表达式，不代表原有适配器不存在。相反，表达式可执行也不自动证明它已经接入运行路径，因此同时保留上表的插件级验收范围。

## 官方依据（2026-09-05 核查）

- [EC2 按需计费](https://aws.amazon.com/ec2/pricing/on-demand/)：实例时间、数据传输、共享传出阶梯边界。
- [EBS 计费](https://aws.amazon.com/ebs/pricing/)：容量、额外预置性能是不同计费项，不能把磁盘费用与实例运行小时混用。
- [RDS MySQL](https://aws.amazon.com/rds/mysql/pricing/) / [RDS PostgreSQL](https://aws.amazon.com/rds/postgresql/pricing/)：按部署类型匹配实例与存储 SKU。
- [ElastiCache 计费](https://aws.amazon.com/elasticache/pricing/)：节点时间、备份、Serverless 分属不同模式。
- [S3 计费](https://aws.amazon.com/s3/pricing/)：不同存储类别的容量、请求、取回和传输维度。
- [ALB 计费](https://aws.amazon.com/elasticloadbalancing/pricing/)：四维取最大值，默认阈值有目标类型与证书等适用条件。

## 验收方法

- `test_executable_billing_rules.py`：Decimal、非法数字、零与缺失、百分比、总量冲突、Redis 拓扑、ALB 最大值、数据盘索引和规则版本。
- `test_primary_rule_plugin_integration.py`：实际插件入口，冻结目录夹具；两个区域标签、ARM/x86 型号、数量变化、双磁盘、RDS 两种引擎和两种部署模式。
- `test_primary_template_billing.py`：S3/ALB 插件真实用量输出、零用量消费、作用域和计算底稿。
- `test_quote_compiler.py`：金额/输入/规则版本/单位/公式底稿漂移被阻止发布。
- 继续运行父子组件快照隔离、清洗边界及完整后端回归；前端构建与组件渲染测试。

冻结夹具用于验证程序算术与接线，不是 AWS 实时报价，也不是在 ARM/x86 两类物理机器上运行程序。上线验收仍需完成客户自然语言 → 确认页 → AWS 实时核价的独立端到端测试。不能把单元测试通过率宣传成客户报价准确率。
