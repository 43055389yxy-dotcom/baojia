# AWS 报价编译器边界与防回退规则

## 目的

这份文档用于防止以后修 Bug 时重新把已经断开的数据链路接回去。核心目标不是“识别更多关键词”，而是让客户换一种说法后，报价仍然使用同一套机器可验证的数据。

## 唯一允许的数据流

```text
客户原话
  -> 第一遍 AI 清洗 + 数字/单位/归属完整性校验（唯一允许读取原话的阶段）
  -> 删除客户原话，只保留清洗后的标准化配置
  -> RequirementIR（客户事实）
  -> ResourceIR（选中云厂商的产品和官方规格）
  -> BillingUsageIR（送给该云厂商官方价目查询的用量）
  -> PriceIR（官方 API 价格；同一计费项连续三次未取得可用费率后可使用同站点官方价格页）
  -> 编译器对账
  -> 客户确认页 / 正式报价
```

任何从后面的阶段返回去扫描客户原话、重新猜数字或覆盖前面事实的路径，都是架构缺陷。

## 清洗完成即断开原话

整单入口必须先把完整客户输入交给第一遍 AI 清洗（包括有销售编号的请求），临时输出标准化配置句和用于完整性校验的原文片段。编号只用于清洗阶段的归属核对，不再作为跳过 AI 或 AI 失败后沿用本地粗识别的快捷路径。第一遍结果只是候选，缺失、冲突和来源不明不得通过改写原文隐去。

第一遍清洗必须先对客户原话做数字、单位和组件归属守恒校验。只有全部通过，才允许把 `original_source_text`、`intake_source_fragments` 及第一遍原文证据全部清空。逐组件官方模板填写、草稿、缓存、重试、日志和报价只接收标准化句；从这里开始，标准化句是唯一逐字证据权威。重复表达只允许在同一组件、字段、值及作用域下合并；单台/总量、前后端、父子资源和不同编号不合并。

第一步组件盘点只负责识别组件身份、编号和原文归属，它产生的是待审核候选，不是最终事实。逐组件 AI 按固定模板完成字段映射并通过 schema、单位、类型、逐字证据和数字守恒校验后，立即标记该组件的语义事实已经封存。

- 正常报价从此只能读取清洗后配置、结构化字段、字段证据和待映射事实，禁止保存、恢复或再运行客户原文正则和关键词规则。
- 第一步盘点中的 `customer_text` 只说明证据来自客户文字，不具有覆盖逐组件清洗结果的权力。
- 只有客户确认页、销售修改或客户纠正产生的明确后续操作可以覆盖已清洗字段，而且必须绑定组件和字段。
- 缓存复用必须重新执行当前清洗后证据校验；不完整就重新调用逐组件 AI，不能恢复原文补齐。
- 旧草稿没有当前 `official-only-v4` 和 `cleaned-only-v1` 标记，或仍含原文时，禁止进入新报价链路并要求从首页重新识别。历史记录不批量删除，但不得作为新流程输入。

## AI 智能体统一官方价格 MCP 路径（2026-09-11）

经过 OAuth 授权的 ChatGPT 或 WorkBuddy 是这条路径中的自然语言推理和价格计算层。AstraQuote 不调用内部 AI 补充、改写或重算智能体的业务决定；MCP 优先调用销售选定云厂商的官方价目 API，保存官方返回证据，并在同一计费项连续三次未取得可用费率后机械核对智能体提交的同站点官方价格页证据，同时执行 schema、事实归属、金额加总一致性和交付状态校验。AWS Pricing Calculator 不再参与查价、验证或交付。不同智能体客户端只能通过同一个公开 MCP 契约访问，同一销售任务仍必须遵守任务所有权和幂等约束，禁止两个客户端同时续跑同一个任务。

职责固定为：

```text
AI 智能体 = 脑子：理解、拆分、选型、数量/作用域判断、官方价格身份选择、单位换算、价格计算、最终业务复核
MCP = 手：云厂商官方价目 API 客户端、原始结果保存、官方价格页证据门槛与站点校验、schema/证据/金额一致性机械校验、XLSX 与销售页面交付
```

销售报价采用“目标规格不向上加价”策略。客户未指定所选云厂商的真实型号时，GPT 把 CPU、内存、容量等数值保留为 RequirementIR 中的目标规格；同区域、同产品存在完全相同规格时选择同规格中总费用最低者，不存在完全相同规格时选择最接近且更便宜的小一档，即使客户资料使用“至少”或“不低于”等措辞也不得由程序自动向上扩容。ResourceIR 必须保留实际官方型号和规格，并用结构化 adjustment 明示“原需求 → 实际报价规格”；程序只验证型号真实可购、价格身份唯一、差异已披露和金额一致，不得自己决定大档或小档。若没有任何更小的可购档位，GPT 才采用该服务最低价的可购基础档并说明其实际规格。客户明确指定且可购的所选云厂商真实型号仍原样保留。

该销售选型政策必须保存在独立的声明式策略文件中，并注入每一张销售报价任务。不得只依赖 MCP 初始化说明，因为客户端可能缓存旧说明；官方价目查询结果只返回官网原始数据，不夹带业务选择规则。程序不得据此替 GPT 选择型号，但必须确保 GPT 在作出选择时收到当前策略版本。

公共 MCP 只能暴露七个工具：

```text
describe_service
get_attribute_values
get_prices
get_price_results
get_quote_job_status
resume_quote_job
build_estimate
```

对授权智能体客户端暴露的稳定 HTTPS 地址是 `/mcp`；OAuth 网关完成认证后再转发到容器内部的 `/v2/mcp`。网关允许 ChatGPT 官方 HTTPS 回调、WorkBuddy 打包连接器和自定义 MCP 的官方自定义协议回调，以及 WorkBuddy 使用 `127.0.0.1` 动态端口的回退回调；不得放宽到任意域名、任意自定义协议或非回环 HTTP 地址。禁止把内部版本路径直接交给销售配置，以免连接地址与 OAuth resource 不一致。

正常路径只有价目查询与核验交付两个主要阶段：

```text
客户原话
  -> 支持 AstraQuote MCP 的智能体整单清洗、组件盘点、数字/单位/作用域守恒
  -> 生成标准化组件清单和 Fact Ledger，随后从正常报价上下文删除原话
  -> get_prices：一次批量查询选定云厂商的官方价目 API
  -> GPT 选择明确产品与全部相关价格维度并计算；同一计费项三次 API 失败后可选择同站点官方价格页
  -> build_estimate：MCP 只核对官方查价批次、Fact Ledger、逐组件金额和整单合计
  -> 程序生成 XLSX、上传私有 S3，并把报价与稳定下载链接返回销售页面
```

`describe_service`、`get_attribute_values` 只在服务代码或属性值不明确时使用。`get_prices` 命中不超过 10 条时返回完整候选；命中超过 10 条或仍有下一页时不得截断后冒充完整结果，而要返回 `needs_refinement`、当前查询、命中数/下界及客观可筛选字段和值，由 GPT 决定如何继续收窄。禁止再维护一套重复的公共产品搜索路径。

`get_prices` 必须支持批量查询。AWS 使用 Price List API 中的 `OnDemand` 和 `Reserved` terms；Azure 使用 Retail Prices API 的即用即付与 Reservation；Oracle Cloud 公共目录只使用 `PAY_AS_YOU_GO`，没有公共合同价证据时不得虚构 1/3 年方案；Google Cloud 使用 Billing Catalog API 的按需与对应产品的 1/3 年承诺使用价格。各云只共用查询、证据和恢复协议，不共享产品、SKU、区域、币种或优惠语义，任何云都不得替代其他云或复用其他云的优惠规则。每个查询必须有稳定 `query_id`并保留官方原始候选、SKU/产品身份、价格维度、币种和分页信息。程序只能做结果数量、字段和证据身份校验，不得挑选单价、估算折扣、换算用量或替换相近 SKU。

`get_prices` 的持久化层保存完整批次，但每次工具响应只返回本次新执行查询的增量和批次级计数，不得反复把历史完整规格树发送给智能体。这里有两种不同的“分批”，不得混淆：桌面对话按每 20 个顶层组件固定拆分，父组件及其子组件必须留在同一批；每个对话内部的官方 API 查询仍由智能体根据查询宽度、分页和预计响应体积动态拆成小组。所有对话和查询小组沿用同一个 `relay_job_id + price_batch_id`，持久化层必须以合并写入保证并行结果不互相覆盖。单次增量超过响应体积预算时，返回查询级摘要、`response_compacted=true` 和可按需读取的 `detail_query_ids`，完整官方响应仍保存在价格批次。智能体需要复查旧结果时，只能通过 `get_price_results` 按明确 `query_id` 小批读取；工具文本摘要不得重复承载 `structuredContent` 的全部原始结果。该边界用于避免大响应挤占上下文或造成页面流式连接中断，不改变官方原始证据的完整保存。

并非所有客户组件都必须找到收费 SKU。GPT 根据官方依据确认不产生额外费用的资源可进入结构化 `zero_cost_services`，其事实必须标记 `disposition=zero_cost`，并绑定官方文档或官方价目证据。Free Tier、Always Free、试用、促销赠送和账户信用额度不属于“不产生额外费用”。价目证据必须绑定具体零费率；若同一 SKU 还存在正常商业费率，编译器必须拒绝其进入零元通道。程序只机械校验组件归属、唯一消费和官方零元身份，不得自动找相近收费产品。

客户没有提供某字段、但官方价格查询必须有该参数时，由 GPT 从官方允许值中选择最小可计价值，并在 `assumptions` 中标注；程序不代替 GPT 填值，也不得用该值覆盖客户事实。

客户未指定必选类别且存在多个合法候选时，正常报价不得因此中断。GPT 必须从当前可验证的官方候选中选择最低费用的最小可计价身份，并记录为 `system_default`；不得伪装成客户事实，必须进入报价文档的调整备注。MCP 不保存服务默认映射，也不能替 GPT 选择。客户明确的产品类型永远优先，禁止用默认值覆盖。

`build_estimate` 接收 GPT 已选择的官方查价证据身份、已计算的逐组件金额与结构化 `fact_id`。`customer_facing` 只属于客户展示元数据，不参与价格证据和事实对账。AstraQuote 禁止维护“客户服务名 → 官方 SKU”的业务映射表，也不得自动换算或改写 GPT 选择。

GPT 必须为每个组件提交依据本批可验证官方价格证据计算出的 `monthly_cost`；证据默认来自 exact/明确选择的官方 API 费率，只有满足三次失败门槛时才可来自同站点官方价格页。公开 MCP 边界将月费机械转换为内部 `expected_monthly_cost`。为兼容 ChatGPT 已冻结的旧工具快照，边界仍接受旧字段 `expected_monthly_cost`，两者同时存在但金额不同时必须停止。程序只校验逐项月费按美分加总后等于 `expected_monthly_total`，不得自行分摊、补造或修改组件费用。任何组件缺少两个字段中的任意一个有效分项月费都必须停止。

`build_estimate` 只在官方价格批次存在、GPT 引用的查价身份可验证、Fact Ledger 唯一消费且逐组件金额与整单合计一致时交付。GPT 负责提交结构化的配置差异、官方限制、系统默认和费用影响；程序只用已核验数据生成固定版式 XLSX，不再调用 AI 改写金额或配置。XLSX 上传到私有 S3，对外只返回 AstraQuote 自有域名下的随机不透明下载令牌。交付必须按销售任务和报价 ID 幂等；价格证据、事实消费、金额一致性、XLSX 生成或 S3 上传未通过时不得写完成回执。系统不再发送企业微信或其他 WebHook。

XLSX 的表格、列宽、费用汇总、冻结窗格和样式完全由程序生成，GPT 不生成 Word、图片或表格文件。工作表直接展示服务明细主表，不再显示报价编号/日期/区域元数据表、报价摘要表或报价口径区块。每个服务占一行，主表固定显示服务、区域、型号/方案、数量、精简配置、该组件月费、参考单价和备注，并在表尾显示合计；仅当报价实际包含预留场景时才增加 1 年/3 年列，不得为按需报价显示无意义空列。各方案栏必须显示客户全部数量的折合月费；全预付方案同时保留整批一次性预付总额，参考单价只能作为官方单位价格依据，不能代替方案金额。没有承诺优惠的持续收费组件必须在承诺方案中沿用按需月费，不得显示为 0。结构化的配置差异、默认值及费用影响必须按 `component_key` 合并到该行最右侧的“备注”列，使用“原需求 → 报价配置（简短客观原因）”的短句，禁止再生成配置调整清单。配置和备注保留型号、容量、节点、主从、高可用、运行时长和计费口径等客户有用事实，但不得出现“最低价”“最便宜”“月费最低”“较低档”“候选中价格最低”“按不超配规则”等内部选型或成本策略。影响客户理解的整单口径必须压缩进各行配置或备注，禁止恢复独立摘要和口径区块。

旧 `prepare_quote / submit_component_first_fill / review_component_fill / validate_quote_draft / start_price_quote / get_quote_status / publish_quote` 七步路径必须物理删除，禁止保留隐藏开关、兼容路由或未来可重新启用的实现。

### 销售前端到智能体的单窗口对话中继

销售首页只负责创建文件队列任务和读取状态，不直接调用任何模型 API。宿主机上的桌面机器人由独立 systemd 工作进程控制，复用管理员已经登录且支持 AstraQuote MCP 的智能体会话，并且只进入现有的 `baojia` 项目；程序不得自动创建、重命名或删除项目。每张销售报价必须创建独立总控对话并保存对话 URL，禁止复用上一张报价的会话上下文。当前经过自动化测试和生产脚本验证的是 Firefox 中的 ChatGPT 适配器；Codex 桌面 Chat 必须在宿主机完成可访问性/页面结构、登录保持、新建对话和历史对话切换实测后才能作为另一适配器启用，禁止仅改名称就宣称已经切换。

整个宿主机只保留一个可见桌面窗口和一份登录状态，不克隆环境、不打开多个应用窗口，也不依赖浏览器标签或窗口句柄。机器人通过持久化的对话 URL 在同一窗口内依次访问多个对话；其他对话的模型生成在服务端继续，因此可以形成并行。全局最多占用 4 个活动报价对话名额，名额属于对话而不是销售人员：1～20 个顶层组件占 1 个名额，21～40 个占 2 个，41～60 个占 3 个，61～80 个占 4 个；更多组件按最多 4 个活动对话滚动处理。一个大型销售任务占用多个名额后，其他销售任务只能使用剩余名额。

第一遍清洗只能在总控对话完成。总控首次提交完整且已清洗的 `quote_components` 后，程序按稳定顺序每 20 个顶层组件拆成一个子批，父组件和全部子组件不得分离。子对话只能收到自己批次的 `component_key`、`customer_owned_source` 和 `billing_scopes`，禁止收到整单原文或兄弟批次。第一批由总控对话处理，其余批次由机器人在同一窗口中新建独立对话；全部对话共享同一个价格批次，后台按组件合并。所有子批停止后，机器人回到总控对话，只做一次最终合并、编译器校验、Excel 和销售页面交付。

每个任务必须绑定自己的 `job_id`、总控对话 URL、子对话 URL、批次编号和组件键。所有活动对话必须轮询访问，禁止用“当前屏幕上的对话”作为全局报价状态。期间只读取各自 DOM，禁止按轮询频率刷新；桌面控制的临时读取超时、连接重试或页面节点重绘必须保留任务为运行中并在下一轮重新定位，不得提前写成失败。页面出现“重试”不得延长任务期限，只允许在等待六十秒、再次确认没有后台完成回执后点击一次。不得启动多个进程并发占用同一登录配置。

报价对话轮询时必须先把实际对话滚动容器移动到最底部。只要当前报价对话出现明确的工具授权卡片，无论插件名称，自动选择“始终允许”；授权动作不得扩展到启动页、其他普通页面或非报价对话。页面重绘导致按钮节点失效时应重新定位，不能把一次临时 DOM 失效判成报价失败。

销售撤回任务时，排队任务立即退出可领取集合并清除原始需求；运行中的任务必须依次访问其总控和子对话、停止仍在生成的回复，并保持其他任务继续运行。任务文件的 `cancelled` 状态具有终态优先级，任何完成或失败回写不得将其恢复。MCP 交付记录必须携带该销售任务编号；生成文件、上传 S3 和写销售页面完成回执前均要重新检查任务仍为 `processing`。上传过程中发现撤回时应删除刚上传的私有对象。

登录状态优先依据现有 ChatGPT 身份会话判断，不能因为项目页暂时没有输入框或只显示“重试”就误报退出登录。只有明确进入登录/退出地址、出现登录控件且不存在有效身份会话时，才把销售任务标记为 `needs_login`。

队列中的 `customer_request` 不进入公开任务响应。浏览器确认消息已经提交后，工作进程必须立即从队列文件删除原始输入并写入 `source_purged_at`；后续 MCP 工具参数只能来自 ChatGPT 首轮形成的标准化组件和 Fact Ledger。登录失效时任务保持 `needs_login`，不得丢弃尚未提交的原始输入；管理员重新登录后任务自动回到队列。

销售任务的进度和完成状态必须来自可验证的机器结果，禁止仅凭页面文字、动画或智能体计划向销售伪报进展。`get_prices` 每次成功写入后按封存的组件计费范围计算真实的完成、失败和待处理数量；销售页只读取这些计数。`build_estimate` 在私有 XLSX、稳定下载地址和页面结构化结果都成功后，必须写入绑定 `relay_job_id + submission_code + quote_id` 的原子 `page_result_ready` 或 `partial_page_result_ready` 回执。后端以该回执作为完成状态的第一依据，并允许它纠正桌面机器人先前因缺少文字标记造成的假失败，但 `cancelled` 永远不可恢复。

同一机器进度指纹连续不变时最多自动续跑 2 次，预算在发送前持久化并跨重启保留；只有新增成功计费范围、完成组件或交付阶段首次向前推进才可以重置。增加失败查询、换 query_id、阶段回退或反复切换不算进展。页面文字变化、授权点击和“重试”按钮不增加期限；页面持续显示正在生成只允许一次有界宽限，之后仍由后台证据决定，不得绕过 2 次上限。两次后仍无进展时，有成功组件就进行一次部分交付：成功组件按官方证据正常列出和合计，失败或待处理组件进入 `unpriced_services`，不得按 0 元、不得计入总额，也不得丢失。部分交付本身失败时保留已有证据并反馈待处理，不能再次进入普通续跑循环。销售可选择“只重试未完成项”，此时复用原价格批次、成功证据和结果，旧部分回执不得覆盖新一代任务。`terminal=false` 或 `must_continue=true` 不授权无限重试；真正权限/配置硬阻塞可以直接停止该项而不浪费两次预算。

部分交付仍校验封存组件集合和计费范围。已核价、明确不收费和未核价组件必须完整、互斥地覆盖计划；已声明但尚未查询的计费范围不能消失。只拿到实例费但缺少该组件其他已声明计费范围时，不能把它标为完整已核价。未核价组件的失败查询不得反过来阻止其他完整组件的部分交付，但错误 envelope、无费率的 `exact` 状态不能充当成功证据或缓存成功。

官方道路缓存与官方价格证据缓存必须分离。道路缓存只能记录已验证的只读接口契约；价格缓存键必须绑定账号站点、地域和完整标准化查询，只能保存带官方身份且含正价商业费率的结果，不能保存客户原话、凭据、免费额度或无费率目录。新鲜结果可机械复用；超出新鲜期后，仅当实时调用被机器分类为 `transport`、`rate_limit` 或 `provider_unavailable` 时，才可在最大陈旧期限内回退到同一查询的最近官方快照，并把观察时间写入销售页内部提示。客户 Excel 禁止展示维护、限流、连接中断、重试、错误码和缓存降级信息。`credentials`、`authorization`、`invalid_request`、签名、道路和响应结构问题不得用缓存遮盖。跨云、跨账号站点、跨地域、跨规格复用必须由编译器阻止。

上游失败必须由后端机器分类并随未核价组件进入交付：凭据/权限属于管理员动作，参数/当地可售规格属于修正动作，维护/限流/连接中断属于有界重试，接口道路或响应结构变化属于适配器动作。销售页面只展示安全类别和处理方向，不展示原始响应、签名或凭据；模型自然语言不得覆盖机器分类，也不得把权限、参数或维护故障统称为“官方无价格”。

收到相同 `client_request_id` 必须返回原销售任务；收到相同 `relay_job_id` 或 `idempotency_key` 必须先返回当前代历史成功结果，再检查任务是否仍为 processing，不得重复查价、生成 XLSX 或写完成回执。`get_quote_job_status` 和 `resume_quote_job` 只暴露保存阶段及下一缺失动作；恢复时复用 `price_batch_id`，只补缺失查询或步骤。没有交付回执且没有最终状态标记的阶段性回复必须视为“尚未完成”。工作进程保持新鲜心跳时，页面短暂无输出不得误判失败；工作进程和任务均停止更新超过宽限期时，后端必须原子结束，禁止销售页面无限显示报价中。桌面中继必须在可见桌面宿主机运行；报价前端、后端、AstraQuote MCP 与 OAuth 保持在同一个 AstraQuote 容器。

报价流程、安全边界、批量调用要求、降级条件和最终状态标记全部属于 AstraQuote MCP 的固定服务说明，禁止由浏览器中继在每张报价的 ChatGPT 消息里重复拼接。每张新对话只能发送本单业务数据：一句使用 AstraQuote 的报价请求、服务端生成的提交码与撤回保护任务编号、销售选择的云厂商/账号站点/首选地域、本次计价选项和客户需求；不得出现工具调用步骤、Fact Ledger 教程、内部字段说明或完成标记模板。这样规则只在插件中维护一份，销售输入保持正常、简短，且插件升级不会要求销售更换提示词。

销售页面和公开任务 API 只显示业务状态，不得暴露 ChatGPT、插件、项目、对话、客户原文清理、Fact Ledger、运行日志或内部错误。首页只保留云厂商、账号站点对应的官方地域列表、需求、该云厂商自己的购买方式和提交操作；购买方式默认只选按需/即用即付，1 年和 3 年方案由销售主动勾选。地域列表来自当前云厂商、当前账号站点的官方公共地域目录，不得根据账号现有资源反推，也不得混入另一云厂商或站点；销售只能从该列表选择，以保证地域代码归属正确。历史任务或外部调用传入列表外地域时，任务入口不得直接失败；该值只能保留为待解析的地理偏好，并把当前云厂商官方地域清单交给 GPT，由 GPT 在同一云厂商、同一账号站点内选择距离最近且可覆盖整套产品的官方地域。该列表只验证云厂商级地域身份，不代表整单每个产品均可购买，最终产品可用性仍由 GPT 依据当次官方资料和官方响应判断。销售地域是整单首选；整套产品不能全部部署时，GPT 只能在同一云厂商、同一账号站点内根据官方产品地域目录选择支持整套产品的相邻地域，并在页面和 Excel 明示“首选地域 → 实际地域”及原因。服务端为每张新任务随机分配 1～9 的一位提交码，但销售页面不得展示该内部校验码。排队、等待登录和处理中必须分别显示对应业务状态，不能把排队任务伪装成正在运行；进度只显示后台真实组件计数，未知时不编造百分比。部分结果明确标注已核价小计，未核价金额显示缺失而非零；只有存在可重试组件时才提供只重试未完成项，重试期间保留已保存结果。业务失败给出安全、可执行的处理方向，技术异常和凭据仅留在后端。所有报价均由公开 API 返回已验证的客户可读服务名称、精简配置、方案金额及 AstraQuote Excel 稳定下载地址；结果页按一组件一行紧凑展示各方案折合月费，页面自动弹出并提供“复制报价、复制下载链接、下载 Excel”，不发送群消息。Excel 文件名必须使用云厂商短名加报价短标识，禁止拼接完整报价名称和完整 UUID。

## 旧路径物理删除（2026-09-07）

- 删除浏览器填表报价执行器、浏览器 AI 操作代理及其备用报价方法；没有开关可以重新启用这条绕过四层编译器的价格路径。
- 删除 AWS/Azure 混合的旧业务选型入口。新统一 MCP 只对 AWS、Azure、OCI 和 GCP 官方价目 API 做分发，不共享或推测各厂商产品语义。
- 删除逐组件 AI 校验失败后转规则补字段并标记成功的回退。失败必须保留具体错误和组件身份，不能制造“已验证”结果。
- 删除“一致性复核仍有问题但先封存、依赖后续问题拦截”的早返回。校验未通过不得写语义成功标记；选中的官方子产品不得继承免费父产品的价格规则。
- 预览、正式报价、确认单存取不再调用旧原文修复链。读取确认链接不得增加组件、重算数量或清除客户已选型号。
- 事实表整理只处理结构化字段及证据。别名折叠、算术检查和官方规格校验保留；这些检查不能成为第二个语义填写者。
- 解析缓存版本升级为 `component-template-v24-cleaned-only`，缓存键绑定官方 schema、父子归属、清洗后配置和显式确认来源。命中后仍需验证字段类型、清洗后证据、算术和当前官方表单；仍含原文的旧结果不再复用。
- 官方字段目录及只读目录采集工具保留，它们不是旧浏览器报价路径。客户需求和确认记录保留；旧 AI 解析缓存可清理，但不可把客户记录当缓存删除。

禁止新增同等功能的“兼容模式”“本地模板兜底”或另一套报价执行器。相关静态边界与行为回归见 `backend/tests/test_single_intake_pipeline.py`。

必须用通用回归测试证明：粗识别把 Worker 数量误放进集群数、把节点 CPU 误放进任务 CPU 时，逐组件 AI 的正确结果能够取代粗识别，且后续任何步骤不会改回去。

## 四层数据各自负责什么

| 层 | 只负责 | 必须包含 | 绝对不能做 |
| --- | --- | --- | --- |
| RequirementIR | 记录客户明确提出的需求 | 组件、字段、数值、单位、每节点/总量、清洗后逐字证据、`fact_id` | 查询价格、写入官方型号规格、保存客户原话 |
| ResourceIR | 记录产品选择和 AWS 官方规格 | 产品身份、区域、型号、客户需求副本、官方规格、事实消费记录 | 重新读取原话、把官方值冒充客户值 |
| BillingUsageIR | 生成 AWS 可计价用量 | service code、usage type、operation、数量、单位、`source_fact_ids` | 猜客户需求、修改产品选择 |
| PriceIR | 保存官方价格结果 | 与用量一致的 API 费率身份，或三次 API 失败后通过门槛校验的同站点官方价格页证据；单价/费用、币种、来源 | 修正需求、补造用量、无依据估价 |

## 需求事实规则

每个会影响报价的客户数字都要成为一条事实，并至少包含：

- 稳定的 `fact_id`
- 所属组件 `component_key`
- 正式字段路径，例如 `requirements.memory_gib`
- 标准化数值和单位
- `per_node`、`total` 等作用域
- 清洗后标准化配置中的逐字证据
- 来源类型和置信度

数字不是靠“在文本里出现过”就算登记成功。它必须被绑定到正式字段。无法确定归属时，可以让 AI 返回候选映射，但候选必须通过允许字段、单位、类型和组件边界验证；仍不确定才进入客户确认，不能直接进入报价。

客户名称、AWS 展示名称和内部适配器路由均不得参与事实表指纹。名称只属于产品识别层；事实表只由组件归属、字段路径、数值、单位、范围和原文证据决定。名称或别名变化不得触发事实丢失、重复登记或重新计费。

## 父子组件归属边界不可逆

复合需求拆成父子组件后，每个组件必须拥有独立的清洗后配置。例如 EKS/ECS 父组件只拥有集群数量，Worker 子组件拥有节点数、CPU、内存和磁盘。拆分完成后，这个归属边界高于旧数据的来源优先级，不能被重新合并。

- 父子组件后续只能读取各自清洗后的 `customer_owned_source`，禁止取得整单原文或扫描兄弟组件。
- 预拆分生成的草稿、缓存、AI 结果、事实表和校验快照只要含原文或缺少当前策略版本就不得恢复。
- 即使新旧字段都是 `customer_text` 等同级来源，旧的整行事实也不得覆盖拆分后的父子字段。
- 客户后续明确确认或修正可以更新字段，但必须带目标组件身份，不能借此把父子组件重新合并。
- 任何涉及解析、拆分、恢复、缓存或对账的修改，都必须用通用回归测试证明：父组件数量不会吸收 Worker 数量，子组件规格不会回流父组件，父组件事实也不会被子组件重复消费。

这条边界适用于所有复合资源，不依赖 EKS、ECS 或任何具体产品名称。

## 客户规格与官方规格必须隔离

示例：客户要求 Redis 16 GiB，最后选择的官方型号有 26.32 GiB。

```text
requested_specifications.memory_gib = 16
official_specifications.memory_gib = 26.32
```

两者都是真的，但含义不同。不得用 26.32 覆盖 16，也不得因为客户原话没有出现 26.32 就把官方规格判成“漏登记”。展示层可以合并显示，计价和对账不能读取合并后的 `specifications`。

## 产品身份切换必须原子迁移

同一组件可能先被清洗为“EC2 自建软件”，随后由产品识别层确定为原生 AWS 托管服务。产品身份一旦改变，字段契约也必须在同一事务中切换，不能只改服务名称而保留旧产品字段。

- 旧产品的目录结果、校验结果和报价跳过状态必须立即失效。
- 目标产品先按自己的 schema 恢复客户事实；若旧字段与目标字段数值相同且原文证据相同，只保留目标字段。
- 无法证明等价的客户事实不得静默删除或猜测，必须继续作为待映射事实并阻止发布。
- schema 迁移必须在事实表指纹快速路径之前执行；产品名称不参与事实指纹，不代表旧字段可以绕过迁移。
- 后续产品匹配和价格适配器只能接收目标产品字段，禁止读取旧产品残留字段。

这条规则适用于所有“自建转托管、通用转专用、旧产品转新产品”的重分类，不依赖 Kafka、MSK 或任何单个服务名称。

## 编译器发布闸门

正式报价只有满足以下条件才能发布：

1. 每个组件 ID 唯一，父子组件关系明确。
2. 所有 `source_fact_ids` 都存在且属于正确组件。
3. 需要计费的客户事实被正确消费；不能漏项或重复计费。
4. 每条价格与提交的用量在 service code、usage type、operation、数量和单位上相同。
5. 完整报价中的每条用量都有价格；部分报价必须明确标记为部分结果。
6. 汇总金额等于价格明细之和。
7. 编译结果生成稳定指纹，便于日志定位和回归比较。

## 字段唯一所有者与算术口径

一条客户原话中的一个计价事实只能拥有一个正式字段。AI 候选、确定性清洗、历史缓存和产品模板即使分别给出了不同字段名，也不能因此把一份容量或流量变成两份收费项。

- “每节点存储 2T”没有明确区分系统盘和数据盘时，只能归属一个磁盘字段；不能同时生成 2T 系统盘和 2T 数据盘。
- 客户明确分别填写“系统盘 100G、数据盘 500G”时，两者是不同事实，必须分别保留。
- `单台值 × 数量 = 总量`属于算术关系。系统生成的总量必须标记为 `system_derived`，不得成为第二条客户事实；客户同时给出单台值和总量时可用来交叉校验，不一致必须停止报价。
- `单节点/单 Broker 容量 × 节点/Broker 数 × 部署数 = 总量`同样属于算术关系。公式必须登记在共享的声明式算术契约中；系统派生总量校验后移除，不能让不同产品插件自行选择单量或总量。
- 通用别名和产品专用字段从同一证据得到同一数值时，只保留产品契约规定的正式所有者；不同证据中恰好相同的数字不得擅自合并。
- 上述规则在公共计价契约和事实表封存之前执行，产品插件不得通过读取顺序决定使用哪一个字段。

该规则适用于磁盘、存储、流量、请求、运行时长、部署数量以及后续新增的计价维度，不依赖任何产品名称。

## 逻辑完整性总保险

四层编译器不仅校验价格，还要校验流程结构：

- 每个 RequirementIR 必须有对应 ResourceIR；部分报价也必须保留一个明确标记为未核价的资源结果，组件不能消失。
- 完整报价中的每条客户事实都必须被资源选择、明确的非计费上下文或 BillingUsageIR 消费。
- RequirementIR 的父组件必须真实存在，ResourceIR 必须保持同一父子关系。
- 组件键不得为空或重复，父子关系不得形成环；这些错误即使是部分报价也不能放行。
- 事实 ID 在整单内唯一；资源和用量不得引用未知事实或兄弟组件事实。
- 系统派生字段只参与算术，不得伪装成客户锁定事实。
- ResourceIR 不得改写 RequirementIR 中的客户规格或客户数量；免费资源不得产生计费用量，未核价资源不得出现在未标记为部分结果的报价中。

这些校验是所有产品共享的发布闸门。新增产品只需正确声明字段和用量血缘，不能自行绕过闸门。

## AWS 官方目录兼容规则

按需与 Reserved 购买方案必须统一经 AstraQuote MCP 读取 AWS Price List API。按需读取官方 `OnDemand` 条款；1 年/3 年预付读取同一官方产品记录中的 `Reserved` 条款，并按期限、付款方式和 OfferingClass 做结构化唯一匹配。不得把本地折扣率、历史报价或账号级 Offering API 当作价目表替代；账号组织策略禁止 Offering API 时，也不得因此放弃 Price List API 中仍可读取的官方 Reserved 条款。

官方目录的查询范围必须由同一个 `official_catalog_region_scope` 规则生成，贯穿目录查询、缓存键、缓存内容、契约指纹和发布前校验。目录发现阶段原本不带区域过滤的空值与 `global`、`Global` 统一为 `global`；区域代码只规范大小写与首尾空格，不合并不同区域。该标识只是目录查询范围，绝不能写回客户区域，也不代表区域型服务缺少部署区域时可以报价。缓存内容与缓存键的产品或范围不一致时必须拒绝复用，不能直接改标签放行。

无版本的旧目录契约仅允许升级到 v2：根据当前已验证计费项重算旧指纹，证明差异仅为区域写法后才迁移元数据。升级不得读取原话、改客户事实或跳过四层校验；产品、区域范围、字段映射或计费项真正变化时仍停止发布。

官方价目 API 是可计费产品的第一价格证据。只有同一组件、计费项和方案使用三个不同 `query_id` 连续尝试，仍只得到 `not_found` 或非权限类 `query_failed`，并且该归属下不存在任何可用 API 费率时，GPT 才可提交当前云厂商、当前账号站点的官方 HTTPS 价格页作为 PriceIR 证据。网页证据必须包含稳定 `billing_key`、方案、官方 URL、页面标题、具体计费项目、地域、币种、正数单位价格、单位、读取时间、简短摘录和三个失败查询 ID；程序只做同归属、次数、官方站点、地域、币种和正价校验，不选择价格或计算金额。凭据/权限失败继续走管理员修复和五分钟预检拦截，不得以网页证据掩盖。只要该归属已有可用 API 费率，网页证据就不得覆盖。

正式商业报价不得应用 Free Tier、Always Free、免费试用、促销赠送或账户信用额度。官方查询层必须保留原始候选，并为 SKU 内每段官方费率提供稳定的机械身份；当一个 SKU 同时含零价额度段与正价商业费率段时，PriceIR 必须明确绑定正价费率身份并按全部客户用量计价，不能先扣除免费额度。编译器不仅机械拒绝可计费资源引用零价费率，也必须校验 `zero_cost_services`：免费额度文字直接拒绝；官方价目依据必须绑定零费率身份；同 SKU 只要还存在正价商业费率就不得作为零元资源。只有官方永久无额外收费、且不存在对应商业费率的资源才能进入零元通道。

该路径仍逐组件清洗、封存事实，再经过四层 IR 和发布校验。AI 解析失败不允许静默采用粗识别结果。正式报价前重新核验目录契约身份与指纹，目录变化、缺失客户信息、未消费事实或未匹配价格仍停止发布。目录字段支持不代表所有条件组合均已可报价。

AWS Price List 在不同区域可能省略 `group`、`productFamily` 等说明性标签，不能因为标签缺失就认定产品不存在。目录适配统一采用两步匹配：

1. 先用区域、`group`、`operation` 等条件做窄查询，提高速度。
2. 窄查询为空时，放宽可选标签，只保留区域，再用稳定的 `UsageType`、`Operation` 和正式产品属性做语义筛选。

回退结果仍必须来自 AWS 官方目录并通过唯一性校验；它不是模糊猜测，也不能用相似名称代替官方计费身份。

## 官方查价道路的验证与自学习

需要签名访问的云厂商不得把每个产品的接口路径、动作和返回结构永久写死在报价逻辑中。GPT 可以在官方文档、官方 SDK、官方 OpenAPI、官方价格计算器及云厂商官方域名内提出新的只读查价道路；程序只负责安全校验、签名、探测、结构验证和持久化。第三方页面最多用于定位官方资料，不得成为正式价格证据；达到上述三次 API 失败门槛后，仅当前云厂商与账号站点的官方价格页可作为正式证据。

只有实际成功返回官方产品身份的只读道路才可写入道路库。记录至少包含 `auth_scheme`、`market_profile`、`credential_scope`、`request_schema_hash`、`response_schema_hash`、`sdk_version`、`last_verified_at`、`failure_count`、`confidence` 和 `official_source_url`，并保存道路版本历史。道路库只保存请求字段路径和类型，不保存字段值；请求中的客户型号、数量、区域以外的业务值和其他报价专属参数不得写入道路库；客户原话、Fact Ledger、报价金额和凭据绝对不得进入道路记录。文档 URL 只是可选元数据：它失效或属于另一站点时应丢弃，并以实际通过验证的官方 API URL 作为证据，不能因此拒绝同批全部有效查询；官方 endpoint、站点、只读动作或响应证据不合法时仍必须拒绝。

后续报价应先按云厂商、当前账号站点、服务和区域在服务端按需检索已验证道路；唯一命中时自动复用，多条不同契约命中时返回精简候选由 GPT 决定，不得把全部道路灌入模型上下文。复用道路时必须重新提交本单业务参数并实时调用官方价格接口，不得复用历史价格。

已验证的成功道路不按日期过期、不因一两个月未使用而删除，改为事件驱动校验。对同一道路只有 `route_not_found` 或 `response_schema` 等证明 endpoint、动作或返回契约本身失效的道路级错误，连续出现三次后才隔离当前版本并让 GPT 重新从官方来源找路；新道路成功后另存新版本，旧版本继续保留供追溯。参数缺失、格式错误、参数值不支持和报价条件不可购属于本单参数经验，只记录字段形状、官方错误码和恢复方向，不计入道路失败次数。限流和临时网络错误只安全重试，也不使成功道路失效。所有可恢复错误都保持报价任务为 `pricing_partial`，不得直接向销售宣告失败。道路库必须使用持久化、带事务的共享存储，确保多个并发报价不会相互覆盖学习结果。

动态道路仍必须经过原有四层 IR 和发布闸门。共享 API 边界只允许查询、描述、列举和询价；创建、购买、支付、续费、修改、绑定、释放或删除资源的动作一律拒绝。TLS 例外只能绑定已确认的单个官方主机，继续验证证书链、禁止重定向并仅用于只读调用，禁止关闭全局证书验证。

### 查询尝试与正式计费项分离

`query_id` 是一次查询尝试，不是客户组件或正式计费项。GPT 用可选 `query_contexts` 声明 `purpose=discovery/pricing`；正式计价查询绑定稳定 `component_key + billing_key + scenario_key`。这些仅为价格批次的工作流元数据，不进入云 API 参数、道路缓存、客户事实或客户原话恢复流程。新旧客户端都沿用现有七个工具。

目录探索不计入正式价格待办。相同云与计费归属下，新尝试成功返回官方费率后，可以替代更早的未完成尝试；仅返回目录 envelope、哈希身份或新尝试仍失败时不得替代。GPT 可用 `supersedes_query_ids` 显式关联无归属的旧批次；已确定的组件、计费项和购买方式不得相互覆盖，不能把正式计价改标为探索来抹去缺项。查询状态和替代关系与完整批次原子保存，失败原始记录保留可读。

`pricing_partial`、`incomplete_query_ids` 只描述查询进度，不能作为禁止 `build_estimate` 的整单门槛。交付仍以 GPT 选中的官方价格证据、所有声明计费项的组件/方案覆盖、事实消费和金额对账为准。最终 PriceIR 只收录实际引用的 API 查询和通过门槛校验的官方价格页证据；未使用的探索、失败及替代历史留在原始批次。该调整不改变四层 IR、零费用验证或父子组件清洗边界。

查询层必须区分官方空列表、筛选后无匹配、返回字段路径缺失和返回类型错误。返回提取前后计数、客观候选字段和恢复方向；失败的原始官方响应保存在批次，可按需读取。字段契约错误明确作为可修正的 `response_schema`，不能伪装成产品不存在。恢复仍由 GPT 判断官方参数与路线，程序不按产品名补业务值。

## 官方价格证据发布路径

所有云厂商统一经 `RequirementIR -> ResourceIR -> BillingUsageIR -> PriceIR -> Excel + 页面结果` 发布。API 优先；满足三次同计费归属失败门槛后，官方价格页证据进入同一个 PriceIR，不另建旁路报价器。不创建、导入、回读或展示任何官方计算器链接。销售选择的云厂商必须绑定任务和官方价格批次；GPT 不得改换云厂商，MCP 不得根据客户文字猜测云厂商。

## 销售页面交付路径

所有报价固定在销售页面显示，并同时提供 Excel；不降低四层 IR、官方价格唯一性、事实消费和金额对账要求：

- 完成 `RequirementIR -> ResourceIR -> BillingUsageIR -> PriceIR` 后返回结构化客户可读结果。
- 结果只包含服务名称、型号/方案、数量、配置摘要、各计价方案逐组件金额和整单合计；禁止返回客户原话、Fact Ledger、查询身份、内部错误或调试信息。
- 该路径生成一次 XLSX、上传私有 S3，并把本站稳定下载地址写入 `page_result_ready` 回执；前端以回执为准弹出并允许复制报价、复制下载链接或直接下载。不调用企业 WebHook。
- 撤回状态仍具有最高优先级；撤回后不得写入页面结果回执，也不得恢复为完成。
- Excel 对外下载使用本站不可猜测的临时令牌，由服务端读取私有 S3；不得把会被聊天平台追加参数而破坏签名的 S3 预签名 URL 直接发给客户。

## AI 的正确位置

AI 可以做：

- 把不同说法归一为正式字段候选。
- 判断字段更可能属于哪个组件或计费维度。
- 在字段未知时解释语义并给出结构化候选。

AI 不可以做：

- 凭空决定或改写官方价格；它可以从通过门槛的官方 API/官方价格页证据中选择计费项并自行计算。
- 绕过 schema 创建任意字段。
- 覆盖已有客户事实。
- 在产品插件内重新阅读整段客户原话。
- 用自然语言答案直接通过发布闸门。

## 处理器架构选择边界

整单 ARM/x86 选择只是所有组件的默认偏好，不是把整份报价强制改成同一种架构。某个组件在当前区域和整单默认架构下没有官方型号时，确认页必须允许客户只为该组件选择另一种架构。

- 单组件例外必须绑定确认项的稳定 `answer_key`，再由服务端映射到唯一组件 ID；禁止按服务名称或问题文案猜归属。
- 单组件例外不得修改整单默认值，也不得影响任何兄弟组件。
- 页面切换后必须清除该组件旧型号，服务端必须再次验证新型号与该组件架构一致。
- 整单默认值和单组件例外都属于工作流元数据，禁止送入 AI、禁止混入客户原话、禁止作为普通需求字段计费。
- 若当前架构无型号，页面必须显示可操作的组件级切换入口和提交阻塞原因；禁止只显示空列表或无说明地禁用提交按钮。

## 修复 Bug 的固定步骤

1. 从异常日志提取失败的组件、事实、用量和价格身份。
2. 判断错误发生在哪一层，不允许跨层打补丁。
3. 先添加不依赖具体产品名称的复现测试。
4. 修复公共 schema、字段映射、单位系统、适配器或编译器规则。
5. 运行当前案例、历史回归案例和完整测试。
6. 用代码搜索确认报价插件没有重新读取 `source_text`。

- [ ] 没有为一句客户原话新增专用关键词补丁。
- [ ] 客户需求与官方规格没有写入同一权威字段。
- [ ] 新增计费用量带有有效 `source_fact_ids`。
- [ ] 用量和价格能一一对应。
- [ ] 官方目录匹配没有把 `group`、`productFamily` 等可选标签当成唯一依据。

- [ ] 页面只在全部必须组件通过后进入客户可见状态。
- [ ] 公共 MCP 只暴露七个正式工具；`build_estimate` 只做官方价格证据、事实和金额机械校验及交付，没有重新引入内部 AI。
- [ ] `get_prices` 在小结果集返回完整官方候选、terms、offerings 和 price dimensions；大结果集返回 `needs_refinement` 且没有截断冒充完整；非唯一结果没有被自动选择。
- [ ] 仓库生产运行路径中没有 Calculator 客户端、浏览器、模板、回读器或手写服务转换器。
- [ ] `build_estimate` 只接收 GPT 决定的 ResourceIR、事实归属、官方 PriceIR 证据和 GPT 计算金额。
- [ ] 官方价格页证据只在同组件/计费项/方案三个不同 API 查询均未取得可用费率后使用；凭据/权限失败不解锁，且有 API 成功证据时禁止覆盖。
- [ ] 父子组件仅使用各自清洗后配置；原文已从新草稿、缓存、日志和重试上下文删除。

- [ ] 单资源值与总量算术一致；不一致时已阻止报价而非任选其一。
- [ ] 含节点/Broker/实例拓扑的单量与总量公式已登记在共享算术契约，而不是散落在产品插件中。
- [ ] 每个需求组件都有资源结果，组件键唯一且非空，父子关系无孤儿、无环并且跨层一致。
- [ ] 资源层未改写客户规格或数量；免费组件无计费用量，未核价组件只存在于明确的部分报价中。
- [ ] 相关回归测试与全量测试通过。

## 兼容旧代码的迁移原则

旧字段可以暂时保留给页面展示，但只能由四层 IR 派生，不能继续作为权威输入。每迁移一个插件，都要把它对客户原话和合并规格字段的依赖删除。迁移期间若发现旧代码缺字段，应回到 RequirementIR 的正式映射或计费契约补齐，不能在插件里重新猜。

## 可执行计费模板（2026-09-05）

五个独立服务模块继续拥有自己的字段、官方依据和计费规则。通用 `billing_rules` 只执行闭集算术表达式，不认识产品名称、不执行 AI 代码、不读取客户原话。插件在官方产品身份已确定后调用模板生成用量；未知收费维度仍必须交给已有的正式目录适配器，不能执行模板中的文字说明。

- AI 提示中的已迁移公式由同一表达式生成，不能再维护第二份实际计算公式。
- 算术使用 Decimal；仅在现有 AWS API 数值边界转换为 float。此变更没有把所有历史金额计算迁移为 Decimal。
- 零是已知用量，缺失是未知用量；零用量不得提交正数计费行，仍须记录事实消费。
- 模板版本指纹覆盖字段、规则、单位和官方依据地址。计算底稿记录输入、规则默认值、作用域、数组项索引和结果，不把派生量写回客户事实。
