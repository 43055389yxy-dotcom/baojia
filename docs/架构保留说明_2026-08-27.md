# AstraQuote 架构保留说明

日期：2026-08-27

本次提交用于保留新一轮底层架构改造前的可运行版本。

## 当前保留版架构

当前版本采用“客户原文参与多阶段处理”的报价流程：AI 负责拆分和识别组件，随后由本地规则、字段恢复、官方目录匹配、组件级校验及客户确认流程逐层补充和修正；EKS Worker、自建软件所需 EC2 等衍生资源在后续流程中拆分并独立报价。

该方案通过多层保护降低 AI 漏识别风险，但同一份原文和同一组字段会在多个阶段被再次读取、恢复或修正，流程较重，也存在服务名称差异、字段互相覆盖以及历史原文重新影响已清洗配置的风险。

## 后续计划架构

后续准备改为“清洗后的结构化配置是唯一需求数据源”的单向流程：

1. 原始输入仅用于第一阶段的组件拆分、服务理解和报价字段提取。
2. 服务名称通过统一产品身份和动态别名匹配本地官方目录，不依赖显示文字完全一致。
3. 通过字段守恒、单位换算和跨字段逻辑校验后，形成不可被后续步骤随意覆盖的客户报价需求。
4. 衍生服务成为正式的父子组件规划层，使用稳定组件编号，独立校验、独立报价，避免重复和串项。
5. 第一阶段验证通过后删除原始长句，后续只读取结构化配置。
6. 官方配置与客户报价需求逐字段对账；不一致、缺失、停用或区域不支持时禁止生成错误报价。
7. 仅重试失败组件，所有必要的客户问题一次性集中展示。

本提交作为旧架构保留点，便于后续对比、回退和复查。
